# ESP32-P4 与 ESP32-S3 选型指南

> 这不是官方参数表的搬运。这里记的是「做项目时真正要考虑的因素」。

## 一句话结论

| 你的需求 | 选 |
|---|---|
| 做视觉、屏幕、视频 | **P4** |
| 做通用 IoT、要 WiFi | **S3** |
| 两个都要 | P4 + C6 双芯片 |

## 一、最容易被忽略的根本差异：P4 没有 WiFi

这是选型时最容易踩的坑。很多人看到 P4 参数比 S3 强就选了 P4，
结果画完板子、打完样，写代码时才发现：

```
undefined reference to `esp_wifi_init`
```

**不是配置问题，是芯片里根本没有射频模块。**

乐鑫的设计思路是把「无线」和「计算」彻底分开：

```
ESP32-P4   =  纯计算（双核 400MHz + 32MB PSRAM + MIPI + H.264）
ESP32-C6   =  纯无线（WiFi 6 + BT 5 + Zigbee/Thread）
     ↓
   SDIO 连接
```

### 三种联网方案

| 方案 | 说明 | 适用 |
|---|---|---|
| **板上自带 C6** | 官方 EV 板就是这么做的，出厂预烧了 esp_hosted 固件 | 买现成开发板 |
| **外挂 C6/C3 模块** | 自己画板时加一颗，SDIO 或串口通信 | 自己打样 |
| **不用无线** | 纯离线设备，数据走 USB/SD 卡 | 视觉终端、HMI 面板 |

如果你板上没有 C6，那 P4 就是个**完全离线的设备**。
做产品前一定要想清楚这一点。

## 二、参数对比（只列对选型有影响的）

| 项目 | S3 | P4 | 影响 |
|---|---|---|---|
| 主频 | 240 MHz | 400 MHz | 算力 1.7 倍，图像处理才用得上 |
| SRAM | 512 KB | 768 KB | 差得不多，真正靠 PSRAM |
| PSRAM | 最大 8 MB | **最大 32 MB** | 4 倍，决定能不能做高分辨率帧缓冲 |
| Wi-Fi | ✅ | ❌ | **决定性差异** |
| 摄像头 | DVP 并口 | **MIPI-CSI** | MIPI 带宽高得多，能上 500 万像素 |
| 屏幕 | RGB/SPI | **MIPI-DSI** | MIPI 能驱 720p@60，RGB 驱 480p 就到顶 |
| H.264 | ❌ | **硬编 1080p@30** | 视频类项目刚需，软编 CPU 直接满载 |
| USB | 1.1 FS | **2.0 HS** | HS 480Mbps，能当 UVC 摄像头 |
| 生态 | 成熟（Arduino 支持好） | 较新（主要靠 ESP-IDF） | 开发效率差异明显 |

## 三、具体场景怎么选

### 场景 A：智能音箱 / 语音助手

**选 S3。**

理由：语音不需要大内存也不需要高分辨率屏幕，
但必须联网（云端 ASR/LLM）。S3 内置 WiFi，一颗芯片搞定。

### 场景 B：门禁摄像头 / IP Camera

**选 P4。**

理由：
- MIPI-CSI 接 500 万像素摄像头
- H.264 硬编码 1080p 不占 CPU
- 32MB PSRAM 能存多帧缓冲
- USB 2.0 HS 直接当 UVC 设备，插电脑免驱

WiFi 用外挂的 C6 解决。

### 场景 C：带屏幕的 HMI 控制面板

**选 P4。**

理由：
- MIPI-DSI 驱 720p 屏，60fps 流畅
- 大 PSRAM 跑 LVGL 不吃力
- 如果有联网需求，看板子有没有 C6

### 场景 D：传感器网关 / 数据采集

**选 S3。**

理由：传感器数据量小，重点是低功耗和联网稳定性，S3 更合适。

### 场景 E：机器人主控

**看情况。**

如果机器人要**做视觉识别**（不只是避障），P4 的 MIPI + PSRAM 优势明显。
如果只是**超声波避障 + 电机控制 + 云端对话**，S3 完全够用，而且省了一颗 C6。

## 四、迁移成本

从 S3 迁移到 P4，代码层面大部分不用改：

| 模块 | 迁移难度 |
|---|---|
| GPIO / I2C / SPI / UART | 几乎零改动（引脚号要重排） |
| FreeRTOS | 零改动 |
| LVGL | 改动小（换显示驱动） |
| 摄像头 | 改动大（DVP → MIPI） |
| WiFi | **必须重写**（改用 esp_hosted 或自己实现） |
| 蓝牙 | **必须重写** |
| Arduino 框架 | 支持有限，建议直接用 ESP-IDF |

**最大的坑是 WiFi 和蓝牙**，其他都好办。

## 五、成本考虑

| | S3 方案 | P4 方案 |
|---|---|---|
| 主控 | ESP32-S3 模块 | ESP32-P4 + ESP32-C6 |
| 芯片成本 | 1 颗 | 2 颗 |
| PCB 复杂度 | 低 | 高（SDIO 走线有要求） |
| 开发周期 | 短 | 长（生态较新） |

**除非真的需要 P4 的视觉/多媒体能力，否则 S3 性价比更高。**
