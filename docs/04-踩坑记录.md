# P4-NANO 踩坑记录（完整版）

> 本文记录从零上手 P4-NANO 到跑通 YOLO 全过程中**实际踩到的坑**。
> 每个坑按「现象 → 排查 → 根因 → 解决 → 预防」组织。
> 共 **16 条**，按发生顺序排列。

---

## 一、工具链与烧录

### 坑 1：`CONFIG_SPIRAM` 配不上（最坑，代号"哑巴坑"）

**现象：**

- `sdkconfig.defaults` 里明明写了 `CONFIG_SPIRAM=y`，但 `set-target` 后 sdkconfig 里**完全没有这一行**
- 手动往 sdkconfig 追加，`idf.py build` 会重新生成并**覆盖掉**
- `idf.py -D CONFIG_SPIRAM=y reconfigure` 后，CMake 警告其他子选项未使用
- **整个过程没有任何报错**

**排查过程：**

1. 先怀疑 sdkconfig.defaults 语法问题 → 换成官方示例的写法，无效
2. 再怀疑 IDF 版本问题 → 换 v5.3、v5.4，都无效
3. 去翻 ESP-IDF 源码找 Kconfig 定义
4. 最后发现：**`esp_psram` 组件根本没被加入构建**

**根因：**

ESP-IDF 的 `MINIMAL_BUILD` 机制下，**未被任何组件依赖的组件不参与构建**，
其 Kconfig 也就不被加载，`CONFIG_SPIRAM` 这个选项**在配置系统里根本不存在**。

`hello_world` 的 `main/CMakeLists.txt` 只有：

```cmake
PRIV_REQUIRES spi_flash        # 只有 spi_flash
```

**解决：**

```cmake
PRIV_REQUIRES spi_flash esp_psram esp_timer esp_hw_support
```

外加（P4 的 PSRAM 是实验特性）：

```ini
CONFIG_IDF_EXPERIMENTAL_FEATURES=y
```

**预防：** 遇到「某个 CONFIG_XXX 配不上」，先想「这个组件在构建里吗」，而不是怀疑配置文件语法。

### 坑 2：sdkconfig.defaults 不能用中文注释（静默失效）

**现象：** 配置项**全部失效**，且**无任何报错**。

**排查过程：** 对着 sdkconfig 逐项检查，发现 `CONFIG_ESPTOOLPY_FLASHSIZE_16MB` 完全不存在。

**根因：**

中文注释把第一个配置项吞进了同一行：

```ini
# ESP32-P4-NANO 硬件配置（实测 16MB...）CONFIG_ESPTOOLPY_FLASHSIZE_16MB=y   ← 全变注释
```

Kconfig 解析器按行处理，`#` 之后整行都是注释。

**解决：** sdkconfig.defaults **必须全英文注释**。

**预防：** sdkconfig.defaults 一律英文注释；改完用 `type sdkconfig | findstr CONFIG_SPIRAM` 确认生效。

---

### 坑 3：Flash 默认只配 2MB，浪费 14MB

**现象：**

```
W (239) spi_flash: Detected size(16384k) larger than the size in the binary image header(2048k).
```

**根因：** ESP-IDF 对 P4 的默认 flash size 是 2MB。

**解决：**

```ini
CONFIG_ESPTOOLPY_FLASHSIZE_16MB=y
CONFIG_ESPTOOLPY_FLASHSIZE="16MB"
```

**预防：** 换板子第一件事——确认 flash size 配置和实际硬件一致。

---

### 坑 4：bootloader 太大装不下

**现象：**

```
Error: Bootloader binary size 0x60c0 bytes is too large for partition table offset 0x8000.
       Bootloader binary can be maximum 0x6000 (24576) bytes
```

**根因：** 启用 PSRAM 后 bootloader 从 `0x5CB0` 长到 `0x60C0`，超过默认 offset `0x8000` 的 24KB 上限。

**解决：**

```ini
CONFIG_PARTITION_TABLE_OFFSET=0x9000
```

同步调整 `partitions.csv` 起始偏移为 `0xA000`。

**预防：** 启用 PSRAM / WiFi / 蓝牙等大组件后，注意 bootloader 体积增长。

---

### 坑 5：改 partitions.csv 不生效

**现象：** 改完 partitions.csv 重新 build，分区表还是旧的。

**根因：** CMake 缓存了上次的分区信息。

**解决：**

```powershell
Remove-Item sdkconfig, build -Recurse -Force
idf.py set-target esp32p4
```

**预防：** 凡是改 `partitions.csv`、`sdkconfig.defaults`、`CMakeLists.txt` 涉及构建结构的，一律先清干净。

---

### 坑 6：esptool 发 SYNC 没回应

**现象：**

```
SYNC 回应 (0 字节): (空)
MAC 命令回应: (空)
```

**根因：** 芯片**没进下载模式**。ROM 在正常启动模式下不响应 esptool 协议。

**解决：** 手动进下载模式：

```
1. 按住 BOOT 键不放
2. 点一下 RST 键
3. 松开 BOOT
4. 串口应输出 "waiting for download"
```

**预防：** 每次烧录前先看串口有没有 `waiting for download`。

---

### 坑 7：端口号每次都变

**现象：** 同一个板子，昨天 COM8，今天插上变成 COM12。

**根因：** Windows 每次重新枚举 USB 设备时可能分配新端口号。

**解决：** **不要写死端口**。

```powershell
# 方法 1：列出所有串口
[System.IO.Ports.SerialPort]::GetPortNames()

# 方法 2：按 VID/PID 精确找（CH343 是 VID_1A86 & PID_55D3）
Get-CimInstance Win32_PnPEntity | Where-Object {
    $_.PNPDeviceID -match 'VID_1A86&PID_55D3'
} | Select-Object Name
```

**预防：** 用本仓库的 `tools/find-port.ps1`。

---

### 坑 8：ESP-IDF v5.5 头文件不再自动包含

**现象：**

```
error: unknown type name 'esp_chip_info_t'
HINT: esp_chip_info.h header file is not included by esp_system.h anymore.
```

**根因：** v5.5 精简了头文件包含关系。

**解决：** 手动加：

```c
#include "esp_chip_info.h"
```

**预防：** 升级 IDF 大版本后，先用最小工程跑一遍，把缺的头文件补齐。

## 二、C6 协处理器 / WiFi

### 坑 9：C6 固件版本不匹配

**现象：**

```
I (3175) eh_init_evt: esp-hosted fw versions: host=3.1.0 coprocessor=0.0.0
E (3175) eh_init_evt: major version mismatch ??? OTA coprocessor from host
I (3185) eh_init_evt: CP without SDIO SW_AGGR; compatible streaming mode enabled
```

**根因：** C6 出厂固件是 `0.0.0`（几乎最原始），P4 程序里的 esp_hosted 是 `3.1.0`。版本差距大。

**影响评估：**

| 功能 | 状态 |
|---|---|
| WiFi STA 连接 | ✅ 正常（实测能拿到 IP） |
| WiFi 数据收发 | ✅ 正常 |
| BLE | ⚠️ 未测 |
| 高性能特性（SDIO 聚合） | ⚠️ 不可用，走兼容模式 |

**解决：**

- **短期**：保持现状。WiFi 能用，够毕设。写进论文「已知限制」章节。
- **长期**：用 esp_hosted 的 OTA 功能把 C6 刷到新版。

**预防：** 买板子时问清楚 C6 固件版本；或者一开始就规划 OTA 升级。

---

### 坑 10：WiFi 组件缺少依赖声明

**现象：**

```
Compilation failed because wifi_test.c includes esp_hosted.h,
provided by espressif__esp_hosted component(s).
However, espressif__esp_hosted is not in the requirements list of "main".
```

**根因：** `main/CMakeLists.txt` 的 `PRIV_REQUIRES` 里没写 `espressif__esp_hosted`。

**解决：**

```cmake
PRIV_REQUIRES ... espressif__esp_hosted
```

**预防：** ESP-IDF 的报错信息很明确，照抄它建议的组件名即可。

---

### 坑 11：非 ASCII SSID 变乱码

**现象：**

```
ssid="Falcons ?????????????????????"
```

中文 SSID「Falcons 青训中心—北京」编译后变成问号，无法连接。

**根因：** 源码文件编码 + 编译器字符集处理。

**解决：**

- 测试用**纯 ASCII** SSID
- 实际部署时从 NVS 或配置文件读取 SSID，不硬编码中文

**预防：** 涉及字符串的配置一律 ASCII，需要中文就放配置文件。

---

### 坑 12：WiFi reason=201 (NO_AP_FOUND)

**现象：** 连 `jiuge_5G` 失败，reason=201。

**根因：** 扫描时该网络不在范围内（实测环境只有 `BITC` 一个网络）。

**解决：** 先确认可用 SSID：

```powershell
netsh wlan show networks
```

**预防：** 烧录前先扫一遍。

## 三、YOLO / ESP-DL

### 坑 13：esp-ppq 要求 Python < 3.13

**现象：**

```
ERROR: Could not find a version that satisfies the requirement esp-ppq
```

**根因：** 默认 Python 是 3.14.6，`esp-ppq` 最高只支持 3.12。

**解决：** 用 Python 3.12：

```
C:\Users\34246\AppData\Local\Programs\Python\Python312\python.exe
```

**预防：** ESP-DL 相关工具链一律用 Python 3.12 虚拟环境，别用系统 Python。

---

### 坑 14：模板的 `override_path` 指向不存在的目录

**现象：**

```
ERROR: The "override_path" field in the manifest file
"p4_yolo_test/esp-dl/idf_component.yml" does not point to a directory.
```

**根因：**

`espdet_detect/idf_component.yml` 里写了：

```yaml
espressif/esp-dl:
  override_path: "../../esp-dl"    ← 这是 esp-detection 仓库内的相对路径
```

单独复制 `espdet_detect` 目录到自己的工程后，`../../esp-dl` 就不存在了。

**解决：** 删掉 `override_path`，改为从组件注册表下载：

```yaml
dependencies:
  espressif/esp-dl:
    version: "^3.2.0"
```

**预防：** 从示例仓库复制组件时，检查所有 `override_path` / 相对路径引用。

---

### 坑 15：模型文件名必须精确匹配

**现象：**

```
ninja: error: 'models/p4/espdet_pico_imgH_imgW_custom.espdl', missing
```

**根因：** `espdet_detect/CMakeLists.txt` 里写死了文件名：

```cmake
list(APPEND models ${models_dir}/espdet_pico_imgH_imgW_custom.espdl)
```

`imgH_imgW` 是字面的占位符，不是变量。你的模型叫别的名字就找不到。

**解决：** 把模型重命名为 `espdet_pico_imgH_imgW_custom.espdl`。

**预防：** 保持原样，别改模型文件名。

---

### 坑 16：官方示例依赖 BSP，微雪 NANO 用不了

**现象：** 编译报找不到 `esp32_p4_function_ev_board` 相关头文件。

**根因：** 官方 `espdet_example_template` 依赖：

```yaml
espressif/esp32_p4_function_ev_board_noglib    ← 官方 EV 板的 BSP
```

微雪 P4-NANO 不是官方 EV Board，没有这个 BSP。

**解决：** 自己写最小 main，不依赖 BSP：

```cmake
set(requires espdet_detect esp_psram esp_timer esp_hw_support)
```

**预防：** 用非官方板子时，官方示例的 BSP 依赖一律要找替代方案。

## 四、其他经验

### 17：SDIO 单次读取不能超过 1536 字节

**现象：**

```
W (xxxx) eh_sdio: preallocated 2 SDIO RX staging slot(s), 1536 bytes each
E (xxxx) eh_sdio: SDIO RX read (2048 bytes) exceeds staging target (1536 bytes)
```

**根因：** esp_hosted 的 SDIO 接收缓冲区每个 slot 只有 1536 字节。
如果一次 HTTP 响应的读取请求超过这个大小，会报错或丢数据。

**解决：** 用 `esp_http_client_read()` 分块读，每块 ≤1024 字节：

```c
char buf[1024];
int len;
while ((len = esp_http_client_read(client, buf, sizeof(buf))) > 0) {
    // 处理数据
}
```

**预防：** 走 SDIO/WiFi 的数据流一律分块读取，别一次全读。

---

### 18：monitor 退不出来

**问题：** 按 Ctrl+C 没用。

**解决：** `Ctrl + ]`

## 六、一句话总结

> **P4 的坑集中在三处：Kconfig 静默失效（坑 1-5）、C6 固件版本（坑 9）、ESP-DL 工具链（坑 13-16）。**
> 前两类都是「不报错但不对」，最耗时间；
> 第三类是「报错但信息不明确」，靠对照本文档能快速定位。
