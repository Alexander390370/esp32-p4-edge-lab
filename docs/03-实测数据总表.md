## 二、分区表实测

### 2.1 最终采用的分区（YOLO 版）

```
# Name,   Type, SubType, Offset,   Size
nvs,      data, nvs,     0xA000,   0x6000,
phy_init, data, phy,     0x10000,  0x1000,
factory,  app,  factory, 0x20000,  0x600000,    # 6MB 应用
storage,  data, spiffs,  0x620000, 0x9D0000,    # 约 9.8MB 存储
```

**为什么 app 分区要 6MB：**
- 基础 hello_world 约 170KB
- 加 esp_hosted + WiFi 约 1.2MB
- 加 ESP-DL + YOLO 模型（567.7KB）+ C++ 运行时 → **3.4MB**
- 留一倍余量 → 6MB

### 3.2 已知问题：固件版本不匹配

```
I (3175) eh_init_evt: esp-hosted fw versions: host=3.1.0 coprocessor=0.0.0
E (3175) eh_init_evt: major version mismatch ??? OTA coprocessor from host
I (3185) eh_init_evt: CP without SDIO SW_AGGR; compatible streaming mode enabled
I (3195) eh_init_evt: Missing SDIO_MODE TLV; Continue anyway.
```

| 项目 | 状态 | 说明 |
|---|---|---|
| host 版本 | 3.1.0 | P4 程序里带的 esp_hosted 组件 |
| coprocessor 版本 | **0.0.0** | C6 出厂固件，几乎最原始 |
| 影响 | WiFi 仍能用 | 但走兼容模式，SDIO SW_AGGR 不可用 |
| BLE | 未测 | 可能需要新固件 |

**这个问题的实际影响：**

- ✅ WiFi STA 能连、能收发数据（已实测）
- ⚠️ 高性能特性受限（没有 SDIO 聚合传输）
- ⚠️ BLE 未验证

**短期方案（毕设够用）**：保持现状，把这一条写进论文「已知限制」章节。

## 五、YOLO 推理实测（核心数据）

### 5.1 结论摘要

| 指标 | 实测值 | 说明 |
|---|---|---|
| **推理帧率** | **14.30 FPS** | 69.95 ms/帧 |
| **单帧延迟** | **69.95 ms** | 稳态平均 |
| **抖动** | **0.1 ms** | 极稳定（69.9~70.0） |
| 首次推理 | 200 ms | 含模型初始化 |
| JPEG 解码 | 90 ms | 640×480 一次性（不计入循环） |
| 模型加载 | ~0 ms | Flash mmap，不占启动时间 |
| PSRAM 占用 | 1.66 MB | 32MB 里用了 1.66MB |
| 模型大小 | 567.7 KB | espdl 格式 |

### 5.2 完整耗时分解

```
[STAGE 1] JPEG decode
          640x480 decoded, 90 ms

[STAGE 2] Model load
          0 ms            ← Flash mmap，不占启动时间

[STAGE 3] First inference (warmup)
          200 ms, 2 objects

[STAGE 4] Steady-state (30 runs)
  Run times (ms): 70 70 70 70 70 70 70 70 70 70 70 70 70 70 70
                  70 70 70 70 70 70 70 70 70 70 70 70 70 70 70
```

**30 次连续推理，每次都是 70ms±0.1**，说明推理耗时是确定的，没有 GC 或内存抖动。

### 5.3 检测结果

```
Detected 2 object(s):
  - category=0  score=0.852  box=[0, 0, 591, 479]
  - category=0  score=0.852  box=[48, 60, 622, 479]
```

⚠️ **重要说明**：`category=0` 在该模型中是 **cat（猫）**，不是 person。
这是 ESP-DL 官方提供的示例模型（`espdet_pico_224_224_cat`），
**只能识别猫，不能识别人**。做安防场景需要自己训练人形模型。

### 5.4 与官方数据对比

| 项目 | 官方 | 实测 | 差异 |
|---|---|---|---|
| espdet_pico 224×224 | 51.4 ms | **69.95 ms** | +36.1% |
| FPS | 19.5 | **14.30** | -26.7% |

**差异原因（已定位）：**

```
70ms（实测） = 51ms（纯推理 224×224） + 19ms（640×480 → 224×224 缩放）
```

官方测试用的是 224×224 原图，我们用的是 640×480 图，多了缩放预处理。

**这不是性能问题，是测试条件不同。**

### 5.5 如何达到官方数据

| 方法 | 预期延迟 | 难度 |
|---|---|---|
| 让摄像头直接输出 224×224（MIPI-CSI 可配） | 约 51 ms | 低 |
| 用 `rect=True` 训练的 160×288 模型 | 45.9 ms（21.8 FPS） | 低 |
| INT8 再优化 | 可能更快 | 中 |
| 双核并行推理 | 理论翻倍 | 高 |

### 5.6 模型转换链路

```
.pt (986 KB)  →  .onnx (1444 KB)  →  .espdl (567.7 KB)
   PyTorch        中间格式             ESP-DL 专用格式
```

**量化压缩了 42%（986 → 568 KB）。**

## 六、与旧方案对比（论文核心论点）

| 方案 | 单次判断延迟 | 提升倍数 |
|---|---|---|
| **原方案**：PC 跑 Qwen3.5-4B 多模态 | **25-30 秒** | 基准 |
| **新方案**：P4 跑 YOLO | **70 毫秒** | **快 357-428 倍** |

**这就是边缘 AI 的意义：把 27 秒的判断变成 70 毫秒。**

### 分级推理时间线（已验证）

```
t=0ms     传感器触发
t=70ms    P4 完成 YOLO → "检测到目标 0.85"     ← 已验证能做到
t=70ms    立即本地告警（蜂鸣器/语音）
t=1.5s    抓图上传 PC（异步）
t=25s     PC 返回深度语义分析
```

**第一级延迟从「假设」变成「实测 70ms」，架构成立。**

## 七、完整可用配置（可直接复制）

### 7.1 sdkconfig.defaults

```ini
# ===== EXPERIMENTAL (P4 PSRAM + hosted 必需) =====
CONFIG_IDF_EXPERIMENTAL_FEATURES=y

# ===== FLASH 16MB =====
CONFIG_ESPTOOLPY_FLASHSIZE_16MB=y
CONFIG_ESPTOOLPY_FLASHSIZE="16MB"
CONFIG_ESPTOOLPY_FLASHFREQ_80M=y
CONFIG_ESPTOOLPY_FLASHMODE_QIO=y

# ===== PARTITION TABLE (bootloader 0x60C0 需要 0x9000) =====
CONFIG_PARTITION_TABLE_OFFSET=0x9000
CONFIG_PARTITION_TABLE_CUSTOM=y
CONFIG_PARTITION_TABLE_CUSTOM_FILENAME="partitions.csv"

# ===== CPU 400MHz =====
CONFIG_ESP_DEFAULT_CPU_FREQ_MHZ_400=y

# ===== PSRAM 32MB HEX 200MHz =====
CONFIG_SPIRAM=y
CONFIG_SPIRAM_MODE_HEX=y
CONFIG_SPIRAM_SPEED_200M=y
CONFIG_SPIRAM_USE_MALLOC=y
CONFIG_SPIRAM_MALLOC_ALWAYSINTERNAL=16384
CONFIG_SPIRAM_MEMTEST=y
CONFIG_SPIRAM_BOOT_INIT=y

# ===== WiFi via C6 (remote) =====
CONFIG_ESP_WIFI_REMOTE_ENABLED=y

# ===== YOLO / ESP-DL =====
CONFIG_FLASH_ESPDET_PICO_imgH_imgW_CUSTOM=y
CONFIG_ESPDET_PICO_imgH_imgW_CUSTOM=y
CONFIG_ESPDET_DETECT_MODEL_IN_FLASH_RODATA=y
CONFIG_COMPILER_CXX_EXCEPTIONS=y
CONFIG_COMPILER_CXX_RTTI=y
CONFIG_ESP_MAIN_TASK_STACK_SIZE=16384
```

⚠️ **必须全英文注释**，中文注释会把配置项吞进注释行（详见踩坑文档）。

### 7.5 esp_hosted 初始化顺序（关键）

```c
// 1. NVS 必须先初始化
nvs_flash_init();

// 2. esp_hosted（C6 协处理器）
esp_hosted_init();
esp_hosted_connect_to_slave();

// 3. 网络栈
esp_netif_init();
esp_event_loop_create_default();
esp_netif_create_default_wifi_sta();

// 4. WiFi
esp_wifi_init(&cfg);
esp_wifi_set_mode(WIFI_MODE_STA);
esp_wifi_set_config(WIFI_IF_STA, &wifi_config);
esp_wifi_start();
```

**顺序错了会「看起来像 NVS 错误、断言失败或静默挂起」。**
